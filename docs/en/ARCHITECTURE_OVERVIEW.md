# Architecture overview

This document summarizes how ORRERY handles tmux, Codex App, the network, local data, and portrait images. Route and internal implementation details are in [Implementation architecture](ARCHITECTURE.md), and the visual specification is in [Design language](../DESIGN.md) (Japanese).

## Agreement with tmux

The agent name must match the tmux session name for a roster jump to work.

Backend startup connects one control-mode connection per live session for the recorder. It does not multiplex all sessions over a single connection. A browser client's pane attach is deferred until the user selects a tile / palette entry.

Operations allowed on ordinary agent sessions:

- attach / detach
- terminal input
- resize / refresh
- viewport claim / follow

The WebSocket protocol's pane `split` / `close` are allowed only for managed sessions with the `orrery-` prefix, and the last remaining pane is never closed. The cockpit's multi-session Split is a non-destructive display layout.

Claim changes the tmux window's grid size and also affects external clients that are open at the same time. Just before the first Claim for each window, ORRERY takes a snapshot of whether a local `window-size` option exists, its value, and the exact grid size. Follow returns every distinct ORRERY-owned window to its snapshot, and the last peer detach / disconnect and teardown also restore only tracked windows.

A plain attach / detach without a Claim does not change external manual settings. A snapshot whose restore failed is kept until it succeeds and retried on later paths; if it still remains at teardown, the session name and window ID are recorded in the backend log.

## Codex App

ORRERY does not read the Codex App snapshot files directly. It shows the rows that the optional orrery-telemetry Codex App Bridge merges into the dashboard `/api/agents`.

A Codex App runtime has no tmux pane, so it cannot be operated from a cockpit terminal. The embedded dashboard uses only the `open` capability, which brings the ChatGPT app to the front. Cold wake and delivery are the Bridge's responsibility.

## Network and offline conditions

At runtime the frontend loads `xterm.js 5.5.0` and `addon-fit 0.10.0` from jsDelivr, and Google Fonts. Without a network, fonts fall back, and if the xterm script cannot be fetched, the terminal UI cannot work. The current distribution is not a fully self-contained bundle.

The backend is localhost-only but has no authentication layer. Do not expose the `/api/*` proxy, terminal input, spawn, EXIT, mail bodies, or the local directory browser through a remote tunnel or a reverse proxy.

## Data and retention

| Data | Location | Retention |
| --- | --- | --- |
| terminal recorder | `ORRERY_HISTORY_DIR`, default `~/.orrery/history` | 7 days normally, 24 hours for orphans |
| pane history | recorder JSON | up to 2000 lines, up to 1000 lines for the attach snapshot |
| root / project / DB settings | `~/.orrery/config.json` | kept after the app is deleted |
| prompt draft / history | WebView / browser `localStorage` | up to 50 entries, until explicitly cleared |
| font / layout / mini / NEW AGENT Advanced settings | `localStorage` | until explicitly reset / cleared |
| ORRERY Mail | external SQLite | ORRERY is read-only |

Deleting the app bundle does not delete this data, the checkout, the venv, the backend process, orrery-telemetry, or tmux sessions. For the specific deletion scope, see [Data locations and uninstall](install.md#data-locations-and-uninstall).

## Portrait asset policy

Portraits are read from three directories: normal (`assets/portraits_64/`), high resolution (`assets/portraits/`), and pixel style (`assets/portraits_px/`, used by the mini-orrery and Planetarium). If one is not found, an initials SVG is returned.

The source asset's URL, SHA-1, revision, author, and license are recorded in `assets/portraits_src/manifest.json`, and credits are collected in [CREDITS.md](../../CREDITS.md). CREDITS.md is generated from the manifest by `scripts/build_portraits.py`. A portrait listed in neither is not treated as an approved distribution asset. The portrait images in `assets/portraits/` and `assets/portraits_64/` are outside the PolyForm Perimeter License, and each image's license follows CREDITS.md.

The 50 pixel-art images in `assets/portraits_px/` were generated by the author, gyroid, with ChatGPT (OpenAI's image generation) from text instructions only. No photographs were used as input. They are distributed under the same terms as the repository (PolyForm Perimeter License 1.0.1).

If you use your own portraits, set a directory outside the repository, and do not mix personal images into the source tree.
